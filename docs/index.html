How much does a language help the programmer avoid production bugs? Each test is a program with one common bug, run in 30 languages.

Overview

The score is the average over all tests, as a percentage. The four categories break it down. Caught before running is the share of tests the compiler refused; no silent failure is the share refused, run correctly or stopped with a clear error. Select a heading to sort.

Compare

Pick up to five languages to see their results side by side. Select a test or a cell to see its detail for just those languages.

How outcomes are scored

A bug refused before the program runs earns a full point, and a build warning that names it earns half: either can keep the bug out of production. A bug the program only shows while running, by stopping with a clear error or by warning and going on, earns a quarter: a test may catch it, but otherwise it reaches production. A wrong answer earns nothing. A warning and a stop never add up; the higher counts. The same holds for every test, compiled or dynamic, logic or memory.

Ignoring a result the language marks must-use counts as a refusal.

A compile error counts as a refusal only if the same program with the bug removed compiles.

N/A means the language cannot attempt the test at all, because it lacks the construct the mistake is made with, such as a mutex or contracts. Those tests score 0, the same as a failure. Where a language can attempt the task, its program does it the way the language allows: a design that makes the mistake impossible runs correctly, like OCaml with no early return, and a missing library call is replaced with what the language has.
