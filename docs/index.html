BreakBench

BreakBench

How much does a language help the programmer avoid production bugs? Each test is a program with one common bug, run in 30 languages.

Score: mean over the tests a language can attempt; every test counts once. It covers the compiler and runtime with their own checks on; no linters, sanitizers or third-party checkers. Python (mypy) is an unranked example of a checker. Language gaps: tests a language cannot attempt for lack of a feature, left out of its score (see Missing features). Details breaks the score down by category.

Each cell reads correct / attempted / total. Correct is points: a refusal or correct run earns 1, a run-time stop 0.5 or 0.25. Attempted below total means a missing feature. Caught before running counts refusals and design-prevented tests.

Each row is a test and each column a language, in rank order. Select a test or a cell to see its evidence below the grid. An outlined cell is a failure the language accepts by design.

Points reflect when the bug is caught and whether it does harm. A refusal stops it before it ships: 1. A clear stop in the shipped build: 0.5. A stop only in the debug build: 0.25. A wrong answer, corruption, crash or hang: 0. A stop counts only if it comes before the result is printed.

Every test counts once. Equal weight per category was tried and dropped: it made one error-handling test worth 3.5 types tests, added noise, and rewarded skipping tests in small categories. Categories group results; they do not weight them.

A right answer earns its point only where the language defines the behavior that gave it. Where the language leaves that behavior undefined or unspecified, the answer is right by chance and earns nothing: another compiler, allocator or input can change it.

Warnings do not score; the Notes tab says why.

A compile error counts as a refusal only if the same program with the bug removed compiles.

N/A: the language lacks a feature the test needs (a mutex, threads, a JSON parser). The test is left out of its score. Prevented by design: the language has the feature and its design rules the error out; 1 point. Unfixable: the error can be made but not fixed; 0.

What each language lacks, and which tests that rules out. Those tests are left out of its score: no penalty, no credit.

How BreakBench builds, runs and scores.

What the score measures

The score measures the language itself: compiler or interpreter, runtime, and the switches that make either refuse more or stop more (checked arithmetic, debug builds, assertions, strict typing). Linters, sanitizers and third-party checkers are left out, even when the language project ships them, since that would measure tooling. Python with mypy is one unranked example.

Checking each result

Every program marks its bug: BREAK! on a line the fix removes, CONTROL! code on a line the fix puts in. Dropping the one and swapping in the other gives the program without the bug.

  • A compile error is a refusal only if the program without the bug compiles and an error points at the bug: a marked line, a line within three of one, the opening line of an enclosing function, match or block, or the declaration of a type a marked line names. Otherwise: Refused Elsewhere, 0.
  • A run that fails the test counts only if the program without the bug, built and run the same way, gives the expected answer; otherwise it is a Benchmark Error. Every such result is checked, except V and Mojo on lost_write_error: neither can detect the failed write (V discards the error; Mojo aborts on an assertion). Tests with no answer of their own give the fixed program one, such as "missing".
  • A build step that runs the program (Clojure) and stops with a run-time error is judged as a run.

Failure modes

Each test covers one mistake, with its CWE, CERT, CVE or pitfall source. Related tests share a failure mode but differ in which check can catch them. missing_argument was removed: it scored like type_confusion in every language.

Tests no language passes

Every language scores 0 on these. They stay, labelled, as hazards no language here guards against.

    Warnings do not score

    Telling whether a warning is about the bug takes a pattern per test, and no pattern is reliable, so warnings never score. Some languages warn far better than others (C and C++ with -Weverything, Scala, C#, Rust, Dart); each result shows the compiler's output, unscored.

    Removed tests

    Any test whose result changes between runs, in any language, is removed. The bench runs three times; all 3,720 results matched, and the two tests changed afterwards matched over five more runs under load. Removed, with the languages that varied (20 runs of one build):

    • concurrent_map_write: unlocked writes to one map. 11 varied: C, C3, C++, Odin (stop or crash); D (hang, wrong answer or stop); Java, Kotlin (hang or wrong answer); Julia (stop or wrong answer); OCaml (stop or hang); F# and Mojo release builds.
    • racy_counter: unlocked increments. C# lost increments in 19 of 20 runs.
    • use_after_close: a write through a freed FILE. C and Nim varied with the allocator's state.
    • hash_matches_equality: equal elements with different hashes. Swift seeds its hash per run: right in 5 of 20.
    • fd_leak: files never closed. Haskell closes handles from a finalizer thread: ran out in 8 of 20.

    check_then_act and async_reentrancy were removed too: a program checks shared state, gives up control (a lock release or an await), then acts on the stale check. Nothing in the program says the two steps belong together, so no compiler or runtime can catch it, and no language could pass.

    Races stay tested by lock_order_deadlock and lost_wakeup, which force one interleaving. Gap: bugs that show only on some runs (unsynchronized writes, per-run hash seeds) are not measured.

    Right by chance

    A right answer counts only where the language defines the behavior. Where it is undefined or unspecified, the program marks the line and a right answer scores 0 as right by chance.

    • C and C++ evaluation_order: both standards leave the order of a call's arguments unspecified; clang happens to run them left to right.
    • V evaluation_order: V emits one C call holding both arguments, so C's unspecified order applies.
    • C3 container_realloc_dangling: the write through a pointer into the list's old buffer is undefined; the allocator happened to grow the list in place or leave the old buffer unused.
    • Zig, Odin, C3 and Mojo state no order for a call's arguments in their references. Their compilers run them left to right, and they keep the point until a reference says otherwise.

    Every other right answer in C, C++, Zig, Odin, C3, D, Mojo, Nim, V and Goose rests on defined behavior.

    N/A and prevented by design

    N/A only when the language lacks the construct the mistake needs (a mutex, threads, a map literal, inheritance, interpolation). Otherwise the program is written the way the language allows and scored; a design that rules the mistake out runs correctly. A missing feature never counts as prevention.

    The one design marker left is unsafe_deserialization: standard decoders build only the declared type. A language with no standard decoder is N/A there. Kotlin uses kotlinx.coroutines for blocking_in_async.

    One scenario per test

    Each test is one program and one input, written the way the language teaches first. A right answer shows the language handled this program, not every input or idiom. The paths that cost points are listed below.

    A forced unwrap is counted once, in forced_unwrap. Where a standard call answers an Option, a Result or an error union, the other tests check it the way the language requires instead of forcing the value out (parse_invalid_number, orphaned_receive). A check the language does not require, such as Go's discarded err, stays out.

    A stop after the answer

    A stop after the result is printed scores as a wrong answer: the wrong value already got out. Examples: Nim empty_max prints 1 before its IndexDefect; unsafe_deserialization, null_byte_path and child_exit_status do harm before any stop.

    Release builds

    What counts as standard

    Allowed: the language and its standard library; libraries the language project itself publishes (Rust regex, Go golang.org/x/text, kotlinx, Haskell aeson); ISO C and POSIX for C and C++; the JVM or .NET class library; every package GHC ships. Not allowed: GNU/BSD extensions, third-party packages, FFI. Each language runs its latest release.

    Other considerations

    • Programs use Option where the standard library returns one, and the default list and integer types. A shared map uses the standard lock-free update where one exists (Clojure atom, Haskell atomicModifyIORef').
    • Each container gets 3 GB of memory and 4,096 processes; each run gets 20 s (reference_cycle, which writes 4 GB, gets 60 s). reference_cycle and lazy_accumulator exceed the cap, so a program that keeps their data runs out of memory: a leak.
    • C-family programs keep stale pointers in data structures, and Rust's huge_allocation passes its buffer to std::hint::black_box, so the optimizer cannot remove the access a real program would make.
    • A compiler crash records ICE and scores 0.
    • Without a sanitizer, C's null dereference and the C-family memory tests run into the hardware or the allocator: a crash, corrupted memory or a wrong answer. C++'s * on an empty std::optional stops through a libstdc++ assertion.
    • GHC's default stack limit is 80% of physical memory, so deep recursion in Haskell reaches the 3 GB cap first and the kernel kills it: stack_overflow crashes.
    • A regex engine that gives up at a backtracking limit and reports no match counts as correct. PHP's preg_match returns false, which reads as no match.
    • V treats the line after a bare return as its value, so it refuses unreachable_code, though not through a reachability check.
    • blocking_in_async uses async/await where the standard libraries can run it, otherwise threads; JavaScript has no blocking sleep, so it runs correctly.
    • OCaml, F#, Haskell and Clojure have no early return, so lock_skipped_on_return unlocks after the conditional and cannot skip it.
    • short_read uses the language's usual process call, so a language whose usual call returns the whole output reads all of it. unflushed_writer is judged by what the file holds after the program exits.
    • PHP runs 8.5, the newest packaged release. Mojo includes MAX for parallelize.
